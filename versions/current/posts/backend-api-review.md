## 先从列表接口开始

博客最常用的是文章列表接口。它需要稳定返回标题、摘要、发布时间、标签和阅读量。

如果接口字段不稳定，前端就会被迫写很多兼容逻辑，页面也容易出现空白或错位。

## 详情接口的重点

详情页需要正文、目录来源、上一篇和下一篇文章。正文可以是 Markdown，也可以是已经渲染好的 HTML。

我更偏向返回 Markdown，让前端保留更高的样式控制权。

## 错误处理

接口报错时不要只返回 `500`。至少要区分：

- 文章不存在
- 草稿不可访问
- 参数格式错误
- 服务内部错误

## 给未来的提醒

接口不是一次写完就结束的东西。它会随着页面形态变化不断演进，最好从一开始就让字段语义清楚一点。
